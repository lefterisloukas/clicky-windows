# Next

Short list of things worth doing soon, in rough priority order.

- **Stream the LLM response.** Today every LLM call (`claude.ts`, `openai-chat.ts`, `openrouter-chat.ts`) is a buffered `await response.json()` — we wait for the full reply before POINT-tag parsing, 2-pass refinement, and TTS even start. Switching to `stream: true` + SSE would let us start pointing and speaking the first sentence while the model is still generating, which is the obvious latency win in the user-perceived loop. Only AssemblyAI's WebSocket is actually streaming today; the ElevenLabs "low-latency streaming" comment in `tts/elevenlabs.ts:9` is misleading — the audio is buffered via `response.arrayBuffer()` and written to a temp file before playback.
- **Collapse the two settings UIs into one.** The chat window has an inline "Setup" panel (`<div id="setup">` at `src/renderer/chat/index.html:841`) with 7 API key inputs + a stripped-down provider/model picker. The tray-opened Settings window (`src/renderer/settings/index.html`) is a strict superset — same keys, plus proxy, voice, window, HIPAA, and the full per-provider model options. Two forms writing to the same `settings.set` IPC, with the chat one being unscrollable (its parent body is `overflow: hidden` and the panel has `flex-shrink: 0`), so a user with all 7 keys filled in can't even see the Save button on small windows. Delete the chat panel + its toggle button + the JS at `src/renderer/chat/index.html:841-901` and `~955-1099`; replace with an empty-state banner in the chat that calls the same `onSettings` tray callback. The tray settings window should get a "no keys configured — add one to get started" hint when everything is empty.
- **Prompt and persona — pull from the previous repo.** The system prompt + persona are missing/timid here. Cross-reference the upstream [farzaa/clicky](https://github.com/farzaa/clicky) repo (and any earlier internal version) and port the full system prompt, voice/persona instructions, and POINT-tag format guidance. The model is currently flying without a clear character.
- **No web search / no internet access for the model.** Every provider (`claude.ts`, `openai-chat.ts`, `openrouter-chat.ts`, `gemini-chat.ts`) sends a single `system`/`systemInstruction` string + the screenshots + the user's text. No `tools: [...]` array anywhere — no Anthropic `web_search_20250305`, no OpenAI `web_search_preview`, no Gemini `googleSearch`. The model is limited to its training data + what's on screen + the last 20 turns of history, and the system prompt doesn't tell it to say "I don't know", so it tends to confabulate on out-of-knowledge questions (weather, current versions, "look up this URL", post-training-cutoff facts). Wire up native web search per provider (one `tools: [...]` line each), gated behind a setting, with a `max_uses` cap to control latency and token cost.
